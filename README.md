# IconPages — плагин для Zim 0.77+

Показывает боковую панель с деревом страниц, где у каждой страницы свой
значок:

1. если на странице явно стоит шорткод `**[ICON=имя]**` — используется он;
2. иначе — обычный значок папки (у страницы есть вложенные) или файла.

Это переписанный с нуля под Zim 0.77 (Python 3 / GTK 3) плагин — обе
старые версии IconTags (0.63, 0.67) написаны под Python 2 / PyGTK2 и
несовместимы с текущим API плагинов Zim (другая система расширений,
другой набор колонок в дереве страниц, другой путь у модуля разбора
токенов и т.д.), так что это по сути новая реализация, а не портирование
кода.

## Переименование из IconTags

Плагин раньше назывался IconTags. Название перестало отражать суть: от
работы с метками в нём остались только два варианта значка по умолчанию
(«есть метки» / «нет меток»), и те убраны — назначение значков отдельным
меткам никогда не поддерживалось, а сам список страниц по меткам и так
даёт встроенный плагин «Метки».

Что нужно знать при обновлении со старой версии:

- папка плагина теперь называется `iconpages` — **старую папку
  `icontags` надо удалить**, иначе в списке плагинов будут оба;
- своя таблица в индексе (`iconlist`) не изменилась, но ключ версии в
  служебной таблице `zim_index` переименован, поэтому при первом запуске
  плагин один раз пересканирует все страницы. Ничего делать не нужно,
  старый ключ `icontags` он подчистит сам;
- настройки плагина и состояние панели хранятся под именем класса
  плагина, которое тоже изменилось, — расположение панели и размер
  значков вернутся к значениям по умолчанию, выставьте заново;
- значки `_default_folder_tags.png` / `_default_file_tags.png` больше не
  используются и из комплекта удалены.

## Установка

Скопируйте папку `iconpages` целиком в:

```
~/.local/share/zim/plugins/iconpages
```

(на Windows — `%APPDATA%\zim\plugins\iconpages`). Значки лежат прямо
внутри папки плагина (`iconpages/icons/`), отдельно копировать их
никуда не нужно — раньше (в версии 0.67) их приходилось отдельно класть в
`data/pixmaps/Tags_Icons` внутри каталога данных Zim, сейчас в этом нет
необходимости. Имя значка в `[ICON=имя]` и имя PNG-файла сопоставляются
без учёта регистра (`Attachment`/`attachment`/`ATTACHMENT` — это одно и
то же, независимо от того, как называется сам файл на диске), так что
регистр можно не согласовывать специально.

Затем в Zim: Правка → Настройки → Плагины → включить «Icon Pages».

## Возможности

- **Боковая панель** — дерево страниц со значками. Ведёт себя так же,
  как встроенная панель «Содержание»: при запуске сразу показывает и
  выделяет уже открытую страницу, а при переключении между страницами
  разворачивает и сворачивает ветки по тем же правилам (пока обе панели
  настроены одинаково — см. «Настройки»). Панель можно использовать и
  **вместо** «Содержания»: отключите встроенный плагин «Page Index» —
  останется одно дерево, со значками и с теми же возможностями.
- **Вставка значка** — меню «Вставка → Insert Icon...» открывает окошко
  выбора, вставляет `**[ICON=имя]**` в текущую позицию курсора.
- **Пересканировать значки** — меню «Сервис → Rescan Icons», перечитывает
  все страницы с диска и обновляет индекс значков. Нужно редко, см.
  раздел «Известное ограничение».
- **Настройки** (Правка → Настройки → Плагины → Icon Pages) —
  расположение панели, размер значков и тот же набор опций дерева, что у
  встроенного «Содержания», с теми же значениями по умолчанию:
  автораскрытие и автосворачивание веток при переключении страниц,
  перемещение страниц перетаскиванием, горизонтальная прокрутка вместо
  многоточия, всплывающие подсказки, линии дерева. Смена любой из этих
  опций применяется к дереву на месте, без сворачивания веток.

### Свои значки: SVG, PNG, ICO

Чтобы добавить свой значок, положите файл в `iconpages/icons/` и
ссылайтесь на него по имени файла без расширения: `cat.svg` →
`**[ICON=cat]**`. Поддерживаются **SVG, PNG и ICO**.

Если для одного имени лежит несколько файлов (`cat.svg`, `cat.png`,
`cat.ico`), берётся первый по приоритету — **SVG → PNG → ICO**, а про
остальные пишется строчка в лог.

SVG предпочтительнее, если вы ставите размер значков больше 16 px:
векторный файл отрисовывается сразу в нужном размере, а растровый
растягивается из фиксированной картинки и мылится.

ICO стоит последним намеренно. Это контейнер растров фиксированного
размера: GdkPixbuf возьмёт из него одну картинку и отмасштабирует ровно
так же, как отмасштабировал бы PNG, — преимуществ перед PNG нет. Формат
поддержан ради готовых виндовых наборов значков; если файл у вас уже есть
в PNG, берите PNG. Старые `.ico` (палитровые, с AND-маской вместо
альфа-канала) могут отрисоваться с рваными краями — это ограничение
формата, а не плагина.

**Важно про SVG:** поддержка SVG не встроена в GdkPixbuf, она приходит
отдельным загрузчиком (librsvg). На большинстве Linux-систем и в обычной
Windows-сборке GTK он есть, но не везде — ядро самого Zim по этой причине
сканирует только PNG. Если загрузчика нет, плагин молча пропустит все
SVG-файлы и напишет в лог предупреждение с их перечислением и со списком
форматов, которые здесь работают; PNG или ICO с тем же именем при этом
продолжит работать. Проверить, что умеет ваша установка, можно так:

```bash
python3 -c "
import gi; from gi.repository import GdkPixbuf
print(sorted({e for f in GdkPixbuf.Pixbuf.get_formats() for e in f.get_extensions()}))"
```

В Debian/Ubuntu загрузчик SVG ставится пакетом `librsvg2-common`.

Имена файлов, начинающиеся с точки, игнорируются.

### Значки по умолчанию

Страницы без шорткода получают `_default_folder` (если есть вложенные
страницы) или `_default_file`. Это обычные файлы в `iconpages/icons/` —
чтобы они выглядели иначе, просто замените их своими, в том числе на
SVG. Отдельной настройки для этого нет и не планируется.

Отдельного диалога для назначения значка метке («Tags Manager») в плагине
нет — он дублировал встроенный плагин «Метки», а собственная реализация
не давала преимуществ. Опции «включить шорткоды» тоже больше нет:
сканирование содержимого — это единственный механизм, которым значок
вообще привязывается к странице, поэтому оно всегда включено. Отключение
плагина, как и раньше, полностью убирает его таблицу из индекса.

## Известное ограничение

Если у страницы несколько разных значений `[ICON=...]` одновременно —
показывается специальный «неоднозначный» значок (синий квадрат-заглушка),
а не какой-то один из них: так проще заметить, что на странице что-то
задано неправильно, чем молча выбрать случайный вариант. Аналогично, для
`[ICON=xxx]` с несуществующим именем показывается красный квадрат.
Чтобы заменить эти заглушки на нормальные картинки, положите файлы
`_no_image.png` и `_several_icons.png` (или `.svg`) в
`iconpages/icons/`.

Красная заглушка также может остаться (даже когда со страницей всё в
порядке) после сбоя сохранения — например, если notebook лежит в папке
DropBox/OneDrive/аналогичного сервиса и тот на мгновение заблокировал
файл во время синхронизации (на Windows это выглядит как ошибка
`[WinError 5] Отказано в доступе`). Сама страница при этом не портится,
но собственный индекс значков плагина может остаться со старым/неверным
значением, и обычная фоновая переиндексация Zim не замечает
рассинхронизации, так как ориентируется на время изменения файла, а не на
содержимое. (Просто перезапуск Zim это не чинит — переиндексация при
старте работает так же.)

Для этого случая и нужен пункт **«Сервис → Rescan Icons»**. Он обновляет
две независимые вещи:

- **файлы значков** — заново читает папку `icons/` и сбрасывает кэш
  отрисованных картинок. Именно это нужно, если вы добавили или заменили
  файл в `icons/`: без сброса кэша плагин продолжал бы показывать
  прежнюю картинку (в том числе красную заглушку `_no_image`) до
  перезапуска Zim;
- **индекс значков** — читает все страницы напрямую с диска и приводит
  сохранённое соответствие «страница → имя значка» в соответствие с их
  содержимым. Заодно удаляются записи для страниц, которых больше нет.

Дерево при этом не сворачивается и не перематывается — модель не
пересобирается, обновления приходят по одной строке за раз.

## Технические заметки (для дальнейшей поддержки)

- `iconutils.py` — загрузка/кэш значков (`GdkPixbuf`), регистронезависимое
  сопоставление имени значка с файлом (SVG/PNG/ICO, в этом порядке
  приоритета), проверка того, какие из этих форматов умеет местный
  GdkPixbuf, разбор шорткода `[ICON=имя]`.
- `indexer.py` — `IconsIndexer`/`IconsView`: свой индексатор содержимого,
  подключается к `notebook.index.update_iter`, хранит `pagename -> icon`
  в отдельной таблице `iconlist` в индексе notebook'а.
- `panelview.py` — `IconsTreeStore` (расширяет `PageTreeStoreBase` из
  `zim.plugins.pageindex`, добавляет колонку со значком),
  `IconsPageTreeView`, `IconPagesPluginWidget` (виджет боковой панели),
  `InsertIconDialog`.
- `__init__.py` — `IconPagesPlugin` + `IconPagesNotebookExtension` (следит
  за индексом на уровне notebook'а — общий для всех окон) +
  `IconPagesNotebookViewExtension` (панель + действия, на уровне окна).

Важный нюанс, на который стоит обратить внимание при доработках: метод
ядра Zim `Index.flag_reindex()` (документированный способ «переиндексировать
всё после подключения нового индексатора») в Zim 0.77.2 задевает не только
файлы страниц, но и случайно попадает в корневую папку notebook'а (у
корневой «страницы» `source_file` совпадает с id корневой папки в таблице
`files`). Это заставляет `update_folder()` в
`zim/notebook/index/files.py` временно пометить все страницы верхнего
уровня как «нужно удалить», и они на короткое время выпадают из индекса
(до следующего прохода). Поэтому в `__init__.py` вместо `flag_reindex()`
используется свой метод `_backfill_existing_pages()` — он читает уже
существующие страницы напрямую через `notebook.get_page(...).get_parsetree()`,
не трогая индекс файлов вообще. Похоже, это баг в самом Zim 0.77.2,
который может проявиться у любого плагина, вызывающего `flag_reindex()`
на уже открытом notebook'е (например, потенциально у `tasklist`, если его
включить на уже проиндексированном большом notebook'е) — возможно, стоит
сообщить о нём в трекер Zim отдельно.

Ещё один нюанс: при перестройке модели дерева (`reload_model()` в
`panelview.py`) GTK сбрасывает состояние развёрнутости веток, так как это
буквально новый объект модели. Поэтому `rescan()` **никогда** не вызывает
`reload_model()` — он полагается на то, что каждая обработанная страница
шлёт точечный сигнал `iconlist-changed`, а тот обновляет конкретную
ячейку значка на месте (`IconsTreeStore.update_page()`). Раньше
восстановление индекса делалось переключением опции в настройках, и
дерево сворачивалось, потому что смена любого preference поднимает
`reload_model()`. Если понадобится ещё один способ принудительно
перечитать значки — вызывайте `rescan()`, а не `reload_model()`, по этой
же причине. На это есть тесты в `tests/test_live_editing.py` и
`tests/test_stale_index_recovery.py` (проверяют и объект модели, и
множество развёрнутых строк).

По той же причине сама перестройка модели сведена к минимуму. Сигнал
`changed` у настроек плагина приходит не только при реальной правке: его
поднимает и пустое OK в диалоге настроек плагина, и — через gio-монитор
файла `preferences.conf` — **любая** перезапись этого файла (сохранение
любых настроек из любого диалога, второй запущенный Zim, задевший файл
инструмент синхронизации/бэкапа): Zim при перечитывании файла эмитит
`changed` даже для не изменившихся значений. Раньше каждый такой сигнал
пересобирал модель и сворачивал раскрытые вручную ветки — со стороны это
выглядело как «деревья в случайный момент разъехались с "Содержанием"».
Теперь `on_preferences_changed()` сверяет размер значков с реально
применённым и пересобирает модель только при его смене, а сам
`reload_model()` перед пересборкой запоминает раскрытые строки и
разворачивает их заново в новой модели.

Сам скан идёт порциями по `BACKFILL_CHUNK` страниц из `GLib.idle_add()`,
чтобы не подвешивать интерфейс на большом notebook'е. Прогресс-диалога
намеренно нет: значки обновляются на месте по мере продвижения, это и
есть обратная связь.
