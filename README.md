# IconPages — плагин для Zim 0.77+

Показывает боковую панель с деревом страниц, где у каждой страницы свой значок:
1. если на странице явно стоит шорткод `**[ICON=имя]**` — используется он;
2. иначе — обычный значок папки (у страницы есть вложенные) или файла.

## Установка

Скопируйте папку `iconpages` целиком в:
`~/.local/share/zim/plugins/iconpages`
(на Windows — `%APPDATA%\zim\plugins\iconpages`).

Значки лежат прямо внутри папки плагина (`iconpages/icons/`), отдельно копировать их никуда не нужно. Имя значка в `[ICON=имя]` и имя PNG/SVG-файла сопоставляются без учёта регистра (`Attachment`, `attachment` и `ATTACHMENT` — это одно и то же), так что регистр можно не согласовывать специально.

Затем в Zim: Правка → Настройки → Плагины → включить «Icon Pages».

## Возможности

* **Боковая панель** — дерево страниц со значками. Ведёт себя так же, как встроенная панель «Содержание»: при запуске сразу показывает и выделяет уже открытую страницу, а при переключении между страницами разворачивает и сворачивает ветки по тем же правилам (пока обе панели настроены одинаково). Панель можно использовать и **вместо** «Содержания»: отключите встроенный плагин «Page Index» — останется одно дерево, со значками и с теми же возможностями.
* **Вставка значка** — меню «Вставка → Insert Icon...» открывает окошко выбора, вставляет `**[ICON=имя]**` в текущую позицию курсора.
* **Пересканировать значки** — меню «Сервис → Rescan Icons», перечитывает все страницы с диска и обновляет индекс значков. Нужно редко, см. раздел «Известное ограничение».
* **Настройки** (Правка → Настройки → Плагины → Icon Pages) — расположение панели, размер значков и тот же набор опций дерева, что у встроенного «Содержания», с теми же значениями по умолчанию. Смена любой из этих опций применяется к дереву на месте, без сворачивания веток.

### Свои значки, PNG и SVG

Чтобы добавить свой значок, положите файл в `iconpages/icons/` и ссылайтесь на него по имени файла без расширения: `cat.svg` → `**[ICON=cat]**`. Поддерживаются **PNG и SVG**.
SVG предпочтительнее, если вы ставите размер значков больше 16 px: векторный файл отрисовывается сразу в нужном размере, а PNG растягивается из фиксированного растра и мылится. Если для одного имени лежат оба файла, берётся SVG, а про второй пишется строчка в лог.
**Важно про SVG:** поддержка SVG не встроена в GdkPixbuf, она приходит отдельным загрузчиком (librsvg). Если загрузчика нет, плагин молча пропустит все SVG-файлы и напишет в лог предупреждение; PNG с тем же именем при этом продолжит работать. В Debian/Ubuntu загрузчик ставится пакетом `librsvg2-common`.
Имена файлов, начинающиеся с точки, игнорируются.

### Значки по умолчанию

Страницы без шорткода получают `_default_folder` (если есть вложенные страницы) или `_default_file`. Это обычные файлы в `iconpages/icons/` — чтобы они выглядели иначе, просто замените их своими, в том числе на SVG.
Сканирование содержимого — это единственный механизм, которым значок привязывается к странице, поэтому оно всегда включено. Отключение плагина полностью убирает его таблицу из индекса.

## Известное ограничение

Если у страницы несколько разных значений `[ICON=...]` одновременно — показывается специальный «неоднозначный» значок (синий квадрат-заглушка). Аналогично, для `[ICON=xxx]` с несуществующим именем показывается красный квадрат. Чтобы заменить эти заглушки на нормальные картинки, положите файлы `_no_image.png` и `_several_icons.png` (или `.svg`) в `iconpages/icons/`.
Красная заглушка также может остаться (даже когда со страницей всё в порядке) после сбоя сохранения — например, если notebook лежит в папке облачного сервиса, и тот на мгновение заблокировал файл во время синхронизации. Обычная фоновая переиндексация Zim этого не замечает, так как ориентируется на время изменения файла, а не на содержимое.
Для этого случая и нужен пункт **«Сервис → Rescan Icons»**: он читает все страницы напрямую с диска и приводит индекс значков в соответствие с их содержимым. Дерево при этом не сворачивается и не перематывается — обновления приходят по одной строке за раз.

## Технические заметки (для дальнейшей поддержки)

* `iconutils.py` — загрузка/кэш значков (`GdkPixbuf`), регистронезависимое сопоставление имени значка с файлом, проверка наличия SVG-загрузчика, разбор шорткода.
* `indexer.py` — `IconsIndexer`/`IconsView`: свой индексатор содержимого, подключается к `notebook.index.update_iter`, хранит `pagename -> icon` в отдельной таблице `iconlist` в индексе notebook'а.
* `panelview.py` — классы `IconsTreeStore`, `IconsPageTreeView`, `IconPagesPluginWidget` (виджет боковой панели) и `InsertIconDialog`.
* `__init__.py` — классы интеграции `IconPagesPlugin`, `IconPagesNotebookExtension` и `IconPagesNotebookViewExtension`.

**Особенности работы с индексом:** В Zim 0.77.2 метод `Index.flag_reindex()` по ошибке затрагивает корневую папку notebook'а, временно помечая корневые страницы на удаление. Чтобы избежать потери данных, плагин не использует этот метод, а применяет собственный механизм `_backfill_existing_pages()`, читающий страницы напрямую (`get_parsetree()`).

**Особенности UI и GTK:**
При перестройке модели дерева (`reload_model()`) GTK сбрасывает состояние развёрнутости веток. Чтобы этого избежать:

1. Функция `rescan()` не вызывает `reload_model()`. Вместо этого она рассылает точечный сигнал `iconlist-changed` для обновления конкретной ячейки.
2. Сигнал `changed` у настроек Zim может срабатывать ложно (например, при перезаписи `preferences.conf` сторонней программой для бэкапа). Метод `on_preferences_changed()` пересобирает модель только при фактической смене размера значков, а перед этим запоминает раскрытые ветки и восстанавливает их состояние.

Для предотвращения зависания GUI фоновое сканирование разбито на порции (`BACKFILL_CHUNK`) и выполняется через `GLib.idle_add()`. Значки обновляются на месте по мере продвижения сканирования.
